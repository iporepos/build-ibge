Harmonized geospatial dataset from the 2000 Brazilian Demographic Census by IBGE

This dataset provides a harmonized geospatial version of the 2000 Brazilian Demographic Census results at the census tract level.

The data are distributed as separate, gzip-compressed files (one per table and per geography layer) together with the script that builds a single GeoPackage from them. The resulting database contains cleaned, standardized, and consistently typed attribute tables linked to the census tract geometries. Variable names were harmonized, data types were explicitly enforced, and structural inconsistencies were resolved or documented to facilitate reproducible spatial analysis and integration with GIS and data science workflows.

The original data source is the 2000 Brazilian Demographic Census conducted by the Instituto Brasileiro de Geografia e Estatística (IBGE): the census tract aggregates of the universe results ("Agregado por Setores Censitários dos Resultados do Universo", one spreadsheet per table and state), the 1:500,000 rural census tract mesh with its administrative boundaries, and the detailed urban census tract maps.

What is in this deposit

Files:

  • attribute tables *.csv.gz — basico, domicilio, morador, responsavel01–05, pessoa01–07, instrucao01–06. One row per census tract, first column setor_code, then the variables V + number (3,230 variables in total).
  • geospatial layers *.gpkg.gz — setores, setoresgrupos, subdistritos, distritos, municipios, unidades and sedes.
  • metadata catalogs: IBGE_CENSO-2000_LAYERS_X_X.csv, IBGE_CENSO-2000_FIELDS_X_X.csv, IBGE_CENSO-2000_VARIABLES_X_X.csv, IBGE_CENSO-2000_CONSISTENCY_X_X.csv — the metadata catalogs and the consistency table (uncompressed, readable on the repository).
  • builder script build_database.py — the script that builds a GeoPackage database from the sources files.

Files are kept separate on purpose, so that new versions of the deposit only replace the files that changed. The .csv.gz files can be read directly by pandas, pyarrow, DuckDB, R and most other tools; the .gpkg.gz files must be decompressed before use in GIS software.

Rebuilding the database

1. Download all files into one folder (keep the .gz files as they are; no need to decompress).
2. Create and edit build_database_2000.json: set input_folder (the folder above), output_folder and the four catalog paths.
3. Run python build_database.py --config build_database_2000.json --overwrite.

Requirements: Python 3 (standard library only) and the GDAL command line tool ogr2ogr available in the PATH. The script reads the compressed files directly (geography layers are unpacked temporarily next to the output and removed), builds the database from zero, and writes a log with checks (row counts, column types, sector key cross-check). The header of the script documents every option of the configuration.

Layers

The GeoPackage has 32 layers, named without census or year (e.g. basico, setores):

  • Geospatial:
      - setores - census tracts, one row per setor_code: rural polygons from the 1:500,000 mesh and detailed urban polygons (geometry_source tells which). Tracts without an own polygon have a null geometry and carry the grupo_code of the group that contains them.
      - setoresgrupos - urban-area polygons of the 1:500,000 mesh that stand for a range of tracts (code UFMMMMMDDSDSSSS-NNNN, first tract and last tract number).
      - subdistritos, distritos, municipios, unidades - the administrative polygons.
      - sedes - points of the municipal seats, linked to municipios by municipio_code.
  • Attribute tables: the 21 tables listed above, linked to setores by setor_code.
  • Four structured metadata layers:
      - layers - Describes all database layers contained in the GeoPackage, including geometry type, spatial reference system, thematic scope, and relational structure where applicable.
      - fields - Documents major attribute fields and naming conventions, including standardized prefixes, identifier variables, geographic codes, and structural variables used for relational integrity and joins.
      - variables - Provides a complete listing of the census variables, including official variable names, harmonized names, and their corresponding descriptions (Portuguese and English) as defined in the 2000 census documentation.
      - consistency - Lists the findings of the geometry harmonization for later revisions (layer, code, issue, measured value, action taken, note).

Together, these metadata layers provide full transparency regarding database structure, schema harmonization, and variable provenance.

Conventions

- Names follow <entity>_code / <entity>_name (e.g. setor_code, municipio_code, municipio_name), with no abbreviations such as "cd" or "nm". Variables are named V + number and identified in variables by variable_code (<table>_<variable>, e.g. domicilio_V0001). The Var01–Var14 columns of the original basico file are V01–V14.
- Identifiers: every column ending in _code is stored as text, so leading zeros and long codes are never altered.
- Variables: columns named V + number are numeric. They are stored as integers, except the variables that actually hold decimals (the averages and variances of basico), which are detected from the data when the database is built and reported in the build log.
- Missing and protected values use fixed codes in every table (documented in the fields layer): -1 hidden for statistical confidentiality and -9999 no data. In the 2000 source IBGE left a cell blank when the value was omitted to protect the respondent, so blank cells are -1; in tracts without population (morador V0237 = 0) a blank cell is 0, the actual value. Text fields use NA for no data or not applicable (including the IBGE placeholders "Não existe / não identificado" and "Não pertence").

Data quality notes

- All 21 tables cover the same 215,811 tracts, with identical keys. The situation and type columns of the original files agreed with basico in every table and are kept only there.
- The 2000 census mapped rural and urban areas separately. In the 1:500,000 rural mesh an urban area is not a hole but a filled polygon coded as a range of tracts (setoresgrupos); the urban tracts inside it come from the detailed urban maps, which do not cover every municipality. The setores layer therefore has 49,424 rural polygons, 127,974 urban polygons and 38,435 tracts without an own polygon.
- In the rural mesh, holes had been exported as extra polygons with the same tract code; they were subtracted back. Where a tract had both a rural and an urban polygon, the urban one was kept. Where ranges were nested, a tract belongs to the narrowest one.
- Six municipalities of the urban maps (2702900, 2708808, 3170107, 3302205, 3304524 and 3522208) had been projected in the wrong UTM zone and were reprojected from the original files; 2708808 still lies about 50 km from its municipality. The urban maps of about twenty other municipalities lie more than 5 km from the rural mesh; they are kept as they are and listed in consistency.
- Coordinates are labeled SIRGAS 2000 (EPSG:4674) but were not datum-transformed: the source maps carry no datum, and they show an offset of about 50–60 m (consistent with SAD69) against current boundaries.
- municipios has 5,509 polygons: the 5,507 municipalities of 2000 plus the two lagoons (Lagoa dos Patos and Lagoa Mirim), which have no seat in sedes.
- Descriptions in the variables layer come from the IBGE documentation of the tract aggregates; the English text was translated for this dataset.
